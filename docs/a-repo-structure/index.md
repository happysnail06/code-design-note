# A. 프로젝트 구성과 실행 흐름

패키지의 역할과 의존 관계, 실행 순서, 경로와 문서 관리 방법을 다룹니다.

## 주제

- **[A1. Adapter와 upstream](a1-adapter-upstream.md)**: 외부 서비스, 외부 라이브러리, 다른 저장소의 코드와 닿는 부분을 adapter 한 곳에 모으고, 가져온 외부 코드는 고치지 않는 방법입니다.
- **[A2. Lazy import](a2-lazy-import.md)**: 일부 기능에서만 필요한 모듈은 그 기능을 실행하는 함수 안에서 import해서, 그 모듈이 없는 환경에서도 나머지 기능이 돌게 하는 방법입니다.
- **[A3. 단일 진입점과 명령 표](a3-entry-point.md)**: 모든 실행, 하위 프로세스까지 하나의 진입점과 명령 표를 거치게 해서 import 경로와 환경을 하나로 맞추는 방법입니다.
- **[A4. 실행 전 전체 검증](a4-validate-first.md)**: 할 일 전체를 plan으로 만들고 모두 검증한 뒤에 첫 단계를 실행하는 방법입니다.
- **[A5. 소스 파일 기준 경로](a5-source-paths.md)**: 경로를 작업 디렉터리가 아니라 소스 파일 위치에서 계산해서, 어디서 실행해도 같은 파일을 가리키게 하는 방법입니다.
- **[A6. 저장소 문서의 역할 분담](a6-repo-docs.md)**: 문서마다 맡는 내용을 나누고, 코드의 설정 표와 문서의 표를 맞춰 두는 방법입니다.
